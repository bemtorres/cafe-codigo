LECCIÓN 01

Modelo y base de datos

Objetivo: Comprender cómo Django representa las tablas mediante clases Python.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

El modelo constituye la estructura de información del sistema. Cada clase que hereda de models.Model representa una tabla; sus atributos representan columnas y cada objeto guardado corresponde a un registro. Django utiliza un ORM (mapeador objeto-relacional), que permite trabajar con Python en vez de escribir manualmente cada sentencia SQL.

Explicación técnica paso a paso

Antes de crear vistas o formularios, se deben definir los datos que necesita el negocio. En este ejemplo, cada producto tiene nombre, precio, stock y estado. Los tipos de campo determinan las validaciones básicas y el tipo de dato que se almacenará.

Ejemplo práctico · Python / Django
# tienda/models.py
from django.db import models

class Producto(models.Model):
    nombre = models.CharField(max_length=100)
    precio = models.DecimalField(max_digits=10, decimal_places=2)
    stock = models.PositiveIntegerField(default=0)
    activo = models.BooleanField(default=True)

    def __str__(self):
        return self.nombre
Ejemplo complementario · Comandos / HTML
python manage.py makemigrations
python manage.py migrate
Atención y buenas prácticas: makemigrations prepara los cambios del esquema y migrate los aplica a la base de datos. Registrar la aplicación en INSTALLED_APPS antes de ejecutar las migraciones.
Actividad de aplicación: Definir un modelo Categoria y relacionarlo con Producto mediante ForeignKey. Explicar por qué se usa on_delete=models.PROTECT.
LECCIÓN 02

Administración con Django Admin

Objetivo: Registrar modelos en el panel administrativo y comprender su utilidad.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

Django Admin es una interfaz de gestión incluida con el framework. Permite consultar, crear, modificar y eliminar registros de modelos registrados, siempre que el usuario tenga permisos. Es una herramienta especialmente útil para pruebas, carga inicial y tareas administrativas internas. No reemplaza automáticamente la interfaz que utilizarán los usuarios finales.

Explicación técnica paso a paso

Para habilitar el modelo se registra en admin.py. Un ModelAdmin permite definir columnas, filtros y búsquedas. El administrador requiere que estén instaladas las aplicaciones de autenticación, sesiones y administración incluidas en la configuración estándar.

Ejemplo práctico · Python / Django
# tienda/admin.py
from django.contrib import admin
from .models import Producto

@admin.register(Producto)
class ProductoAdmin(admin.ModelAdmin):
    list_display = ('id', 'nombre', 'precio', 'stock', 'activo')
    search_fields = ('nombre',)
    list_filter = ('activo',)

python manage.py createsuperuser

Atención y buenas prácticas: El superusuario tiene acceso amplio. Para un entorno real se deben crear cuentas con permisos mínimos y evitar compartir credenciales.

LECCIÓN 03

Listar registros: SELECT, vista y tabla HTML

Objetivo: Recuperar registros desde el ORM y enviarlos a una plantilla.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

La vista recibe una solicitud HTTP, consulta el modelo y construye el contexto que se entrega a una plantilla HTML. La plantilla presenta los resultados al usuario. Esta separación ayuda a mantener el acceso a datos en Python y la presentación en HTML.

Explicación técnica paso a paso

Producto.objects.all() genera un QuerySet. Es posible ordenarlo, filtrarlo o limitarlo antes de mostrarlo. En el HTML, el lenguaje de plantillas de Django permite recorrer cada registro con for y acceder a sus atributos. No se deben escribir consultas SQL dentro de la plantilla.

Ejemplo práctico · Python / Django
# tienda/views.py
from django.shortcuts import render
from .models import Producto

def listado_productos(request):
    productos = Producto.objects.all().order_by('nombre')
    return render(request, 'tienda/listado.html', {
        'productos': productos
    })
Ejemplo complementario · Comandos / HTML
<!-- templates/tienda/listado.html -->
<table>
  <thead><tr><th>Nombre</th><th>Precio</th><th>Stock</th></tr></thead>
  <tbody>
    {% for producto in productos %}
    <tr>
      <td>{{ producto.nombre }}</td>
      <td>{{ producto.precio }}</td>
      <td>{{ producto.stock }}</td>
    </tr>
    {% empty %}
    <tr><td colspan="3">No hay productos registrados.</td></tr>
    {% endfor %}
  </tbody>
</table>
Atención y buenas prácticas: Definir una ruta en urls.py y verificar que el nombre de la plantilla coincida. El bloque empty evita mostrar una tabla aparentemente rota cuando no existen registros.
Actividad de aplicación: Agregar una columna Estado y mostrar “Disponible” cuando stock sea mayor que cero.
LECCIÓN 04

Crear registros con formularios HTML y POST

Objetivo: Procesar el envío de un formulario desde la misma vista.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

El método GET normalmente muestra la página y el formulario; POST envía datos al servidor para solicitar la creación del registro. La vista puede atender ambos métodos: en GET devuelve el formulario vacío y en POST lee, valida y guarda los valores. La operación de escritura nunca debe confiar ciegamente en los datos recibidos.

Explicación técnica paso a paso

Se utiliza request.POST.get() para obtener los campos del formulario. El nombre de cada input debe coincidir exactamente con la clave consultada. El token CSRF protege contra solicitudes falsificadas. Se recomienda convertir números dentro de un bloque try, comprobar rangos y redirigir después de guardar para evitar envíos duplicados al actualizar la página.

Ejemplo práctico · Python / Django
# tienda/views.py (fragmento)
from decimal import Decimal, InvalidOperation
from django.shortcuts import render, redirect
from .models import Producto

def crear_producto(request):
    error = None
    if request.method == 'POST':
        nombre = request.POST.get('nombre', '').strip()
        try:
            precio = Decimal(request.POST.get('precio', ''))
            stock = int(request.POST.get('stock', ''))
            if not nombre or precio < 0 or stock < 0:
                raise ValueError('Datos fuera de rango')
            Producto.objects.create(nombre=nombre, precio=precio, stock=stock)
            return redirect('listado_productos')
        except (InvalidOperation, ValueError, TypeError):
            error = 'Revisa el nombre, el precio y el stock.'
    return render(request, 'tienda/crear.html', {'error': error})
Ejemplo complementario · Comandos / HTML
<form method="post">
  {% csrf_token %}
  <label>Nombre <input name="nombre" required maxlength="100"></label>
  <label>Precio <input name="precio" type="number" step="0.01" min="0" required></label>
  <label>Stock <input name="stock" type="number" min="0" required></label>
  <button type="submit">Guardar producto</button>

Atención y buenas prácticas: No utilizar ProductoForm ni ModelForm en este curso. La validación HTML mejora la experiencia, pero siempre debe repetirse en el servidor.
Actividad de aplicación: Crear un producto y comprobar que aparece en el listado y en Django Admin. Probar el envío de un precio inválido.
LECCIÓN 05

Editar y eliminar registros

Objetivo: Actualizar registros existentes y realizar eliminaciones controladas.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

Editar consiste en recuperar un objeto existente, mostrar sus valores actuales y guardar los cambios. Eliminar consiste en localizar un registro y borrarlo de forma explícita. Ambas acciones deben trabajar con un identificador único y controlar el caso en que el objeto solicitado no existe.

Explicación técnica paso a paso

get_object_or_404 devuelve una respuesta 404 cuando el registro no existe. En la edición, GET muestra el formulario precargado y POST actualiza el objeto. La eliminación debe confirmarse y ejecutarse mediante POST, no mediante un simple enlace GET, porque GET no debe producir cambios destructivos.

Ejemplo práctico · Python / Django
# tienda/views.py (fragmentos)
from django.shortcuts import get_object_or_404, redirect, render
from decimal import Decimal, InvalidOperation

def editar_producto(request, pk):
    producto = get_object_or_404(Producto, pk=pk)
    error = None
    if request.method == 'POST':
        try:
            nombre = request.POST.get('nombre', '').strip()
            precio = Decimal(request.POST.get('precio', ''))
            stock = int(request.POST.get('stock', ''))
            if not nombre or precio < 0 or stock < 0:
                raise ValueError()
            producto.nombre = nombre
            producto.precio = precio
            producto.stock = stock
            producto.save()
            return redirect('listado_productos')
        except (InvalidOperation, ValueError, TypeError):
            error = 'Los datos ingresados no son válidos.'
    return render(request, 'tienda/editar.html', {'producto': producto, 'error': error})

def eliminar_producto(request, pk):
    producto = get_object_or_404(Producto, pk=pk)
    if request.method == 'POST':
        producto.delete()
        return redirect('listado_productos')
    return render(request, 'tienda/confirmar_eliminar.html', {'producto': producto})
Ejemplo complementario · Comandos / HTML
<!-- templates/tienda/confirmar_eliminar.html -->
<h2>¿Eliminar {{ producto.nombre }}?</h2>
<form method="post">
  {% csrf_token %}
  <button type="submit">Confirmar eliminación</button>
</form>
<a href="{% url 'listado_productos' %}">Cancelar</a>
Atención y buenas prácticas: En editar.html se usan los mismos campos HTML del formulario de creación, con value="{{ producto.nombre }}" y valores equivalentes para precio y stock. La URL debe enviar pk a la vista.
Actividad de aplicación: Editar el precio de un producto y confirmar el cambio; después eliminar otro producto desde la pantalla de confirmación.
LECCIÓN 06

Mensajes de éxito, advertencia y error

Objetivo: Informar al usuario el resultado de sus operaciones.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

El framework de mensajes de Django permite mostrar avisos temporales después de una operación. Por ejemplo, al guardar un producto se muestra “Producto creado correctamente”; al eliminar, “Producto eliminado”. Los mensajes mejoran la claridad del flujo y permiten distinguir acciones exitosas de errores o advertencias.

Explicación técnica paso a paso

Los mensajes se agregan desde la vista y se leen desde la plantilla. Con la configuración habitual de Django, pueden mantenerse durante una redirección. Es importante distinguir un mensaje informativo de una validación: mostrar un mensaje de éxito no demuestra por sí solo que los datos sean correctos.

Ejemplo práctico · Python / Django
# tienda/views.py (fragmento)
from django.contrib import messages

# Después de crear correctamente:
messages.success(request, 'Producto registrado correctamente.')
return redirect('listado_productos')

# Después de eliminar correctamente:
messages.warning(request, 'Producto eliminado.')
return redirect('listado_productos')
Ejemplo complementario · Comandos / HTML
<!-- En una plantilla base -->
{% if messages %}
  {% for message in messages %}
    <div class="alerta {{ message.tags }}" role="status">
      {{ message }}
    </div>
  {% endfor %}
{% endif %}
Atención y buenas prácticas: Verificar que django.contrib.messages, su middleware y su context processor estén habilitados. No exponer contraseñas ni datos sensibles en mensajes.
Actividad de aplicación: Agregar mensajes al crear, editar y eliminar, y comprobar que aparecen después de cada redirección.

LECCIÓN 07

Autenticación: login, logout y sesiones

Objetivo: Comprender cómo Django identifica usuarios y mantiene una sesión autenticada.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

Autenticación significa verificar la identidad de quien intenta ingresar; autorización significa decidir qué puede hacer una vez identificado. Django incorpora un sistema de usuarios y sesiones. Tras un inicio de sesión correcto, el navegador recibe una cookie de sesión; el servidor utiliza esa referencia para asociar solicitudes posteriores con el usuario autenticado. La contraseña no se guarda directamente en la cookie.

Explicación técnica paso a paso

authenticate comprueba las credenciales y login registra al usuario en la sesión. logout termina la sesión autenticada. El formulario de acceso utiliza POST y CSRF; las contraseñas deben tratarse con el sistema de hashing de Django, nunca guardarse como texto plano. Es recomendable cerrar sesión mediante POST.

Ejemplo práctico · Python / Django
# cuentas/views.py
from django.contrib.auth import authenticate, login, logout
from django.shortcuts import render, redirect
from django.views.decorators.http import require_POST

def iniciar_sesion(request):
    error = None
    if request.method == 'POST':
        usuario = request.POST.get('username', '')
        clave = request.POST.get('password', '')
        user = authenticate(request, username=usuario, password=clave)
        if user is not None:
            login(request, user)
            return redirect('listado_productos')
        error = 'Credenciales incorrectas.'
    return render(request, 'cuentas/login.html', {'error': error})

@require_POST
def cerrar_sesion(request):
    logout(request)
    return redirect('iniciar_sesion')
Ejemplo complementario · Comandos / HTML
<!-- cuentas/login.html -->
<form method="post">
  {% csrf_token %}
  <input name="username" autocomplete="username" required>
  <input name="password" type="password" autocomplete="current-password" required>
  <button type="submit">Ingresar</button>
</form>
{% if error %}<p role="alert">{{ error }}</p>{% endif %}

<!-- Botón de salida en una página autenticada -->
<form method="post" action="{% url 'cerrar_sesion' %}">
  {% csrf_token %}
  <button type="submit">Cerrar sesión</button>
</form>
Atención y buenas prácticas: Django necesita SessionMiddleware y AuthenticationMiddleware. En producción, usar HTTPS y revisar las opciones de seguridad de cookies.
Actividad de aplicación: Probar credenciales válidas e inválidas, ingresar a una página y verificar que al cerrar sesión se pierde el acceso.
LECCIÓN 08

Proteger vistas con login_required

Objetivo: Restringir páginas a usuarios que hayan iniciado sesión.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

Una página no queda protegida por ocultar su enlace en el menú. Un visitante podría escribir directamente su URL. El decorador login_required comprueba en el servidor si request.user está autenticado; si no lo está, redirige al acceso configurado. Esto permite proteger listados, formularios y operaciones de mantenimiento.

Explicación técnica paso a paso

El decorador se coloca sobre la función que atiende la ruta. Debe aplicarse a todas las vistas que requieren autenticación, no solamente al index.     return render(request, 'tienda/listado.html', {'productos': productos})

LECCIÓN 09

Autorización por perfiles y permisos

Objetivo: Distinguir perfiles y restringir funcionalidades según responsabilidades.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

Un sistema puede tener usuarios autenticados con funciones diferentes. Por ejemplo, un administrador mantiene productos y un operador solo consulta el inventario. Django proporciona usuarios, grupos y permisos. Los grupos pueden representar perfiles organizacionales, mientras que los permisos permiten expresar acciones concretas. Esto es más seguro que confiar únicamente en el nombre de un perfil mostrado en la interfaz.

Explicación técnica paso a paso

La autenticación responde “¿quién eres?”; la autorización responde “¿puedes hacer esto?”. Para un ejemplo sencillo se puede asociar el usuario a un grupo y comprobarlo desde la vista. En proyectos más grandes conviene usar permisos de Django y asignarlos a grupos desde el panel de administración. La verificación debe hacerse en cada vista protegida.

Ejemplo práctico · Python / Django
# Ejemplo con permisos nativos de Django
from django.contrib.auth.decorators import login_required, permission_required

@login_required
@permission_required('tienda.add_producto', raise_exception=True)
def crear_producto(request):
    # Procesar formulario HTML y request.POST
    ...

# Ejemplo de consulta de grupo:
def es_administrador(user):
    return user.is_authenticated and user.groups.filter(
        name='Administradores'
    ).exists()

LECCIÓN 10

Crear decoradores personalizados

Objetivo: Centralizar reglas de autorización reutilizables.

Abrir video en YouTube

¿Qué aprenderás y por qué es importante?

Cuando varias vistas necesitan la misma regla, repetir condiciones en cada función produce código duplicado y aumenta el riesgo de errores. Un decorador personalizado envuelve una vista, comprueba una condición antes de ejecutarla y permite o rechaza el acceso. Puede servir para comprobar grupos, estados de cuenta o reglas específicas del proyecto.

Explicación técnica paso a paso

Un decorador recibe una función y devuelve otra función que la envuelve. functools.wraps conserva metadatos de la vista. En este ejemplo se exige autenticación y pertenencia a un grupo; si no se cumple la regla se devuelve HTTP 403, que significa acceso prohibido. Es importante diferenciarlo de 401 o de una redirección al login.

Ejemplo práctico · Python / Django
# cuentas/decoradores.py
from functools import wraps
from django.contrib.auth.decorators import login_required
from django.core.exceptions import PermissionDenied

def grupo_requerido(nombre_grupo):
    def decorador(vista):
        @wraps(vista)
        @login_required
        def envoltura(request, *args, **kwargs):
            if not request.user.groups.filter(name=nombre_grupo).exists():
                raise PermissionDenied
            return vista(request, *args, **kwargs)
        return envoltura
    return decorador

# Uso en tienda/views.py
from cuentas.decoradores import grupo_requerido

@grupo_requerido('Administradores')
def eliminar_producto(request, pk):
    # Recuperar objeto y confirmar borrado mediante POST
    ...
